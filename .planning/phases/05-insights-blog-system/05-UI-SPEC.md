# Phase 5 — UI Design Contract

> Visual and interaction contract for the Insights (Blog) System. Generated by
> gsd-ui-researcher from 05-CONTEXT.md (D-01..D-14, all locked by Jon), the
> Phase 2 design system (`src/styles/global.css` `@theme` block), and the
> Phase 4 chrome conventions (`AttorneyLayout`, `FaqAccordion`,
> `AttorneyCard`). No new tokens. No new colors. No new component library.
> All decisions below are the lowest-mass thing that satisfies BLOG-01..06,
> BLOG-09, SEO-04, LEGAL-09 and reads as **premium-but-warm** at the same
> volume as the Phase 3 homepage and Phase 4 attorney/practice pages.

## Design System

| Property | Value |
|----------|-------|
| Tool | none (Astro 6 + Tailwind v4, tokens-as-source-of-truth in `src/styles/global.css` `@theme`) |

**Token reuse rule (binding, inherited from Phase 2 D-22 + Phase 3 D-22 retrofit):**
Every value in this contract maps to a token already defined in
`src/styles/global.css`. **Do NOT add a new token. Do NOT hardcode a hex
literal anywhere.** If a value below feels "almost right but not quite,"
the answer is to reuse the existing token, not to invent one — the eight
section components from Phase 2 set this precedent and Phase 5 must hold to it.

## Spacing Scale

The site's spacing scale is fluid (`clamp()`-based) and lives in `@theme`.
The phase-5 surfaces use the existing tokens only:

| Token | Value (resolved) | Usage in Phase 5 |
|-------|------------------|------------------|
| `--spacing-gutter` | `clamp(1.25rem, 0.75rem + 2vw, 2rem)` (~20–32px) | Horizontal page gutter — `px-gutter` on every `/blog` and `/blog/[slug]` container |
| `--spacing-section` | `clamp(2.13rem, 1.34rem + 3.74vw, 4.27rem)` (~34–68px) | Vertical section rhythm — `py-section` on the index header, on the post header block, and around the author card |
| Tailwind `gap-2` | 8px | Chip-row inter-chip spacing |
| Tailwind `gap-3` | 12px | Chip-row inter-row spacing (authors row → practice row) |
| Tailwind `space-y-6` | 24px | Inter-item vertical rhythm in the post list |
| Tailwind `space-y-4` | 16px | Inter-paragraph rhythm inside MDX prose (overridden by the `.prose` class below) |
| Tailwind `mt-10` | 40px | Gap between post body and author card |
| Tailwind `mt-12` | 48px | Gap between author card and disclaimer |

**Vertical rhythm contract for MDX body (post page):**

- Paragraph-to-paragraph: `1.5em` (matches reading-line spacing; not 2em — too magazine-y).
- H2-to-following-paragraph: `0.75em` top, `0.5em` bottom (heading hugs the paragraph it introduces, per Norm Law restraint).
- H3-to-following-paragraph: `0.5em` top, `0.4em` bottom.
- List item-to-item: `0.5em`.
- Blockquote: full-bleed inside the measure, `2em` top + bottom margin to set it apart.

**Exceptions:** none.

## Typography

The site uses **one typeface** (Hanken Grotesk, locked Phase 2 D-05/D-06) at
**fluid clamp() sizes** locked in `@theme`. Phase 5 introduces NO new sizes
and NO new weights — it reuses the existing scale.

| Role | Token | Resolved size | Weight | Line height | Usage in Phase 5 |
|------|-------|---------------|--------|-------------|------------------|
| Body | `--text-body` | `1.0625rem` (17px) | 400 | 1.625 (loose, reading-optimized) | MDX paragraph text, post-list summary, chip labels |
| Body large | `--text-body-lg` | `1.1875rem` (19px) | 400 | 1.55 | Post-page lead paragraph (first `<p>` after the title; planner discretion to render via CSS `:first-of-type`), author-card focus line |
| Small | `--text-small` | `0.875rem` (14px) | 500 | 1.5 | Byline ("By Jon Van Loo · May 28, 2026"), practice-tag pill on post-list items, empty-filtered-state copy |
| H3 | `--text-h3` | `clamp(1.3125rem, 1.15rem + 0.8vw, 1.625rem)` (~21–26px) | 700 | 1.25 | Post-list item title, MDX `<h2>` inside the body, author-card name |
| H2 | `--text-h2` | `clamp(1.75rem, 1.4rem + 1.75vw, 2.5rem)` (~28–40px) | 700 | 1.2 | None on /blog index, none on post body — H2 in MDX renders as `--text-h3` per the prose rule below (the post H1 already carries the page weight) |
| H1 | `--text-h1` | `clamp(2.25rem, 1.6rem + 3.25vw, 3.5rem)` (~36–56px) | 700 | 1.15 | "Insights" on `/blog`; post title on `/blog/[slug]` |
| Display | `--text-display` | reserved for homepage Hero only (Phase 2 D-08) | — | — | **NOT USED in Phase 5.** Display weight stays exclusive to the home hero so the Insights surface reads as "section," not "another landing page." |

**MDX `<h2>` → `text-h3` rationale:** the post `<h1>` is the page H1.
Anything below an H1 inside reading prose at full H2-clamp size (40px on
desktop) starts to fight the headline — and a partner-firm thought-leadership
post is text-dense, not section-heavy. Render `<h2>` at `--text-h3` (semantic
H2, visual H3); render `<h3>` at `--text-body-lg` + weight 700. This matches
the restraint of the Phase 4 attorney bios (where the `<h2>` "Bar admissions
/ Education / Focus" labels also render at H3-scale).

**Measure (reading-line length) for the post body:** `max-w-prose`
(Tailwind default = 65ch). Container is `mx-auto max-w-prose px-gutter` on the
post-body wrapper. **Why 65ch, not the homepage's `max-w-6xl` or attorney
page's `max-w-4xl`:** body prose is the only surface on the site where
character-count is the right constraint, not pixel width. 65ch lands the
desktop measure at ~720px (just under the 800px the attorney page uses for
mixed two-column content) — the post body is one-column, so it can sit
narrower without looking starved.

**Tabular elements (lists, bylines, dates):** proportional figures
(default). No CSS `font-variant-numeric: tabular-nums` anywhere in Phase 5
— the date appears once per post and once per list item; tabular numerals
would read as a calendar grid, which is not the tone.

**Link styling inside MDX body (the single most consequential typographic
contract of this phase, since the post body is the only large prose surface
on the site):**
- Color: `text-accent` (deep rust `#9C3F2A`, contrast 6.8:1 on white — AAA).
- Underline: ALWAYS visible at rest (`underline decoration-1 underline-offset-2`). Underline-on-hover is not enough — accessibility readers and reduced-motion users need rest-state affordance, and the M&A practice-area links on the Phase 4 pages already use this pattern.
- Hover: `decoration-2` (thicker underline) on `motion-safe:hover`.
- Visited: same as rest (no separate visited color — visited-color
  customization adds a maintenance surface for no real benefit on a
  thought-leadership blog where every post may be re-read).
- External links: `rehype-external-links` (already in `CLAUDE.md` Recommended
  Stack) adds `target="_blank" rel="noopener noreferrer"` and a small `↗`
  glyph via `::after`; the glyph is `aria-hidden`. Inline glyph color =
  `text-accent` (same as the link itself).

## Color

The site palette is locked Phase 2 D-01 (cool near-black minimalist,
amended to value-swap by global.css D-32). Phase 5 reuses every token
unchanged. No new color introduced.

| Role | Token | Value | Usage in Phase 5 |
|------|-------|-------|------------------|
| Dominant (~60%) | `--color-bg` | `#ffffff` | Page background, post body, every chip-row surface |
| Secondary (~30%) | `--color-bg-elevated` + `--color-border` (`#e4e4e7`) | `#ffffff` / `#e4e4e7` | Author card surface (the only floating-card surface on the post page); inactive chip background |
| Text dominant | `--color-text` | `#111111` | Post title, post body, author-card name, active-chip label |
| Text muted | `--color-text-muted` | `#52525b` | Byline, post-list summary, practice-tag pill, empty-filtered-state copy, author-card focus line |
| Accent (~10%) | `--color-accent` | `#9c3f2a` | **Reserved list below — never on a chip background, never on a paragraph fill** |
| Primary (button fill) | `--color-primary` | `#0a0a0a` | "Get in touch" CTA at bottom of empty-filtered-state. The active chip uses near-black fill (`bg-text` / `bg-primary` — same value, semantic choice). |
| Accent-fg | `--color-accent-fg` | `#ffffff` | (not used in Phase 5 — no accent-filled surfaces in this phase) |

**Accent reserved for (the explicit list — this is a CONTRACT, not a guideline):**

1. **Inline links inside MDX post body** (color + underline).
2. **Author name in the byline** (it's a link to `/attorneys/[slug]` — same TextLink primitive used site-wide).
3. **"Read [First name]'s full profile →" link on the author card** (same TextLink primitive).
4. **The chevron / "→" glyph after an accent link** — inherits accent via `currentColor`.
5. **Focus-visible ring on every interactive element** (`ring-accent`) — chips, author card, links, the empty-filtered-state reset link. This is the site-wide A11Y-05 contract.
6. **The accent dot before the chip-group label** (see Chip Row visual spec below) — a 4px `bg-accent` dot before "Filter by attorney" / "Filter by practice area" — same vocabulary as ApproachBand's `h-1 w-10 rounded-full bg-accent` accent rule, scaled down.

**Accent is NEVER used for:**
- Chip backgrounds (active OR inactive) — the active chip is near-black fill, not accent. Rationale: rust on a near-white field is high-energy; we want the chip row to feel like quiet utility, not a focal point. The chevron / link affordances inside the row supply rust at typographic scale only.
- Post-list item backgrounds, hover surfaces, or borders.
- Practice-tag pill backgrounds (those are muted-text inside a hairline border, never rust).
- Cover-image borders or overlays.
- The disclaimer block.

**Destructive color:** not introduced in Phase 5. There is no destructive action surface in the Insights flow (filtering is non-destructive; resetting filters is restorative, not destructive).

## Component Contracts

The Phase 5 contract introduces **two new Astro components** and **two
edits to existing files**. Everything else reuses Phase 2/3/4 primitives.

### NEW: `FilterChipRow.astro` (D-06)

**Location:** `src/components/sections/FilterChipRow.astro`

**Purpose:** the two-row chip filter above the post list on `/blog`.

**Props:**
```ts
interface ChipOption { value: string | null; label: string; ariaLabel?: string }
interface Props {
  label: string;                  // "Filter by attorney"
  paramName: 'author' | 'practice'; // URL query-param key
  options: ChipOption[];          // first option is the "All" chip with value: null
  activeValue: string | null;     // current URL-param value (server-resolved)
  otherActiveParams: Record<string, string | null>;  // so a chip click preserves the other axis's filter
}
```

**Visual spec:**
- Row container: `flex flex-wrap items-center gap-2`. Two-axis stack outside (parent supplies `gap-3` between the two FilterChipRow instances).
- Label: `<p class="mb-2 flex items-center gap-2 text-small font-medium uppercase tracking-wide text-text-muted">` with a `<span class="block h-1 w-1.5 rounded-full bg-accent" aria-hidden="true"></span>` accent dot before the text. The label sits ABOVE the chip row, not inline — gives screen-reader users a clear "Filter by attorney → [list of chips]" sequence.
- Each chip is an `<a href>` (NOT a `<button>` — for the unfiltered default and JS-disabled case, the href must work natively; the chip's job is "navigate to a URL," not "fire a callback"). Astro pre-renders 20 combinations cheaply (5 authors × 4 practices) — but we don't pre-build them; the href just sets the query params and the same `/blog` route handles them on render.
- Chip rest state: `inline-flex items-center rounded-full border border-border bg-bg-elevated px-4 py-1.5 text-small font-medium text-text-muted transition-colors duration-150`.
- Chip hover (`motion-safe`): `motion-safe:hover:bg-text/[0.04] motion-safe:hover:text-text`.
- Chip active state (`aria-pressed="true"`): `bg-text text-bg border-text` (near-black fill, white text, no border seam). **No accent fill** — accent is reserved per the Color section.
- Chip focus-visible: `focus-visible:outline-none focus-visible:ring-2 focus-visible:ring-accent focus-visible:ring-offset-2 focus-visible:ring-offset-bg` (site-wide A11Y-05 contract).
- Min hit area: `py-1.5 px-4` produces a ~32px height — too small. Bump to `min-h-[44px]` via either `py-2` or an explicit `min-h-` class to meet WCAG 2.5.5. **Locked: `min-h-[44px] px-4` (44px touch target — the executor calibrates `py-` to land at exactly 44px given the text-small line-height).**

**Interaction contract:**
- Unfiltered default (no JS): `<a href="/blog?author=jon-van-loo">` causes a full page navigation; the index re-renders with the new server-resolved `activeValue`. Works without JS (BLOG-05 baseline).
- Progressive enhancement (`<script>` in `index.astro`, ~30 lines, no framework): the script intercepts chip clicks, calls `history.pushState`, hides the post-list items whose `data-author` / `data-practice` attributes don't match the new query params, and updates `aria-pressed`. This makes filter switching feel instant on a fast partner laptop while staying fully degradable.
- URL contract: `?author=<attorney-slug>&practice=<practice-slug>`. Both optional. Order-stable (author first, then practice — for shareable-URL determinism).
- Empty-filtered state: when the script (or the server render) finds zero matching post-list items, it hides the `<ul>` and reveals a sibling `<div role="status" aria-live="polite">` containing the empty-filtered-state copy (see Copywriting Contract).

**Keyboard contract:**
- Chips are `<a>` elements — they receive focus via Tab natively. **Do not implement custom arrow-key navigation** for this phase. Rationale: arrow-key roving-tabindex is the right pattern for a radiogroup with 50+ options or where horizontal arrow nav is established convention (a date-picker, a tab-strip with a hidden panel beneath). With 5 + 4 = 9 chips total and each chip carrying its own visible affordance, Tab is the simpler and more discoverable navigation — and matches the site-wide pattern where every other interactive element (SiteHeader links, AttorneyCard, FaqAccordion summary, buttons) is Tab-navigated.
- `aria-pressed` (not `aria-selected`, not `role="tab"`): the chip is a toggle, not a tab — there is no associated panel that opens/closes per-chip. Each click navigates; `aria-pressed` is the correct ARIA mapping for "this toggle is currently on" (WAI-ARIA Authoring Practices).
- The chip-row label is associated with its row via `aria-labelledby` on the container `<div>` pointing to the label's `id`.

**Reduced-motion:** the `transition-colors duration-150` hover effect is wrapped via `motion-safe:` — under `prefers-reduced-motion: reduce`, the hover snaps without animation. Focus rings are NEVER motion-gated (Phase 2 D-10).

### NEW: `AuthorCard.astro` (D-09)

**Location:** `src/components/sections/AuthorCard.astro`

**Purpose:** the horizontal bottom-of-post author block.

**Props:**
```ts
interface Props {
  attorney: CollectionEntry<'attorneys'>;
}
```

**Visual spec:**
- Container: `flex flex-col gap-6 sm:flex-row sm:items-center mx-auto max-w-prose rounded-card border border-border bg-bg-elevated p-6 shadow-card`.
- **Important — narrower than AttorneyLayout's header:** AttorneyLayout uses a 120×120 headshot. AuthorCard uses **80×80** (`h-20 w-20`). Smaller because (a) the post page just spent 800–1500 words on the writer, so the headshot is reinforcement not introduction; (b) the post measure is `max-w-prose`, much narrower than `max-w-4xl` — a 120px headshot would dominate.
- Headshot: `<Image src={d.headshot} alt={d.headshotAlt} width={160} height={160} class="h-20 w-20 rounded-card border border-border bg-bg-elevated object-cover" />` (160×160 source, 80×80 display — for retina). Image processed through Astro `<Image>` (PERF-03), lazy-loaded by default (`loading="lazy"` is the Astro default for non-priority images).
- Right column: name (text-h3 weight 700, `<a href="/attorneys/[slug]">` wrapping it — entire name is the link); role (text-small uppercase muted, matches AttorneyCard role chrome exactly — design system coherence); focus line (text-body muted, one line, the `data.focus` field verbatim — same field surfaced by the AttorneyCard "focus" prop on the homepage); CTA line ("Read [First name]'s full profile →" — TextLink primitive).
- On mobile (`<sm`): stacks vertically (`flex-col gap-6`); headshot centers horizontally and the text block sits below it.
- No hover-lift on the card itself. Rationale: the card is not a clickable surface — only the name and the CTA inside it are. A hover-lift on a non-clickable card creates a deceptive affordance. The AttorneyCard on the homepage CAN hover-lift because the whole card IS the link.

**Reusability:** even though only `/blog/[slug]` consumes this component in
Phase 5, the component is small and self-contained — if a future surface
needs "this attorney, with one-line context" (e.g. a v2 "Recent posts by"
band on the attorney profile page itself), this is the reusable primitive.
**Do not duplicate this markup inline in `BlogPostLayout`.** Build the
component.

### Cover image strategy

**Locked: optional, rendered inline at the top of the post body (between
byline and prose), constrained to the prose measure, aspect-ratio
16:9.** Three reasons over a full-bleed hero band:
1. The site already has one bold hero — the homepage. A blog post that
   opens with another full-bleed image dilutes the brand's "minimal,
   premium, restrained" foundation.
2. A constrained 16:9 image inside the prose column reads as illustration
   (supporting the text), not as a magazine cover (replacing the text).
   Matches the Norm Law restraint.
3. Many posts (especially Jon's crypto-tax seed) genuinely don't have a
   strong cover image. Making cover optional + inline lets a coverless post
   render without an awkward empty band.

**When the seed post chooses a cover (D-13 / Jon's call at format step):**
- Format: SVG (preferred — pairs with the existing hero/icon vocabulary and
  stays well under the 200KB budget) OR `.webp` (if a photographic source).
- Aspect: 16:9 (1280×720 source, displayed at the prose measure width).
- Alt text: required (`coverAlt`), descriptive — names the subject and
  conveys the analytical posture (e.g. `Abstract converging tax-line
  illustration in deep rust on white`).
- Lazy-loaded: Astro `<Image>` defaults to `loading="lazy"`; do NOT set
  `loading="eager"` on cover images (only the homepage hero is eager).

**When the seed post omits a cover:** the post page goes title → byline →
prose directly. No placeholder grey rectangle. No "Photo coming soon."

### Article JSON-LD (D-11, SEO-04)

`buildArticleLd(post, author)` in `src/lib/jsonld.ts` returns
`WithContext<Article>`. Fields (locked):

| Field | Source | Notes |
|-------|--------|-------|
| `@context` | `'https://schema.org'` | (schema-dts handles this in the `WithContext` wrapper) |
| `@type` | `'Article'` | Per BLOG-04 wording. Not `'BlogPosting'`. |
| `headline` | `post.data.title` | |

| `publisher` | LegalService blob reused from `buildLegalServiceLd()` minus `@context` | Coherence with site-wide LegalService |
