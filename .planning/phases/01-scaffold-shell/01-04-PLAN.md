`getStaticPaths()` pattern for dynamic routes (RESEARCH.md §"`src/pages/attorneys/[slug].astro` (dynamic route)"):
```typescript
export async function getStaticPaths() {
  const entries = await getCollection('attorneys', ({ data }) => !data.draft);
  return entries.map(entry => ({
    params: { slug: entry.data.slug },   // String, NEVER number — Astro 6 requires (FOUND-10, Pitfall 12)
    props: { entry },
  }));
}
```

Since Plan 02 seeded all placeholders with `draft: true`, `getStaticPaths()` returns an EMPTY array — Phase 1 ships zero dynamic-route pages. That is correct. Phase 4 toggles `draft: false` on real attorney bios.

The `render(entry)` pattern for body content (RESEARCH.md):
```typescript
const { entry } = Astro.props;
const { Content } = await render(entry);
// Then in the body: <Content />
```

`/practice-areas/`, `/attorneys/`, `/blog/` index routes use `getCollection(...)` to enumerate non-draft entries and render a list. In Phase 1 these lists will be empty (all entries are draft); the routes must still render a graceful empty state so the disclaimer crawl test sees a real page.

Astro 6 + the `@astrojs/sitemap` integration auto-generates the sitemap. The sitemap includes every page that built — index pages + any non-draft dynamic-route pages. Since dynamic routes are empty in Phase 1, the sitemap shows: `/`, `/about`, `/contact`, `/practice-areas`, `/attorneys`, `/blog`, `/404`, `/500`. (Note: 404/500 may or may not appear in the sitemap depending on Astro defaults — that's fine; the crawl test walks `<loc>` entries.)
</interfaces>

<rationale>
The branded 404 and 500 routes are static `.astro` files that Astro emits as `dist/404.html` and `dist/500.html`. Vercel uses these when no route matches (or a server error occurs). They MUST use BaseLayout so they include the footer disclaimer — the crawl test does not test these explicitly (they may not be in sitemap), but they're required by FOUND-05 + LEGAL-01 (disclaimer on every page, period).

The three dynamic-route shells (`[slug].astro`) ship with `getStaticPaths()` filtering out drafts. Since every Plan 02 placeholder is `draft: true`, Phase 1 ships ZERO dynamic-route pages. This is by design — Phase 4 toggles `draft: false` on Aaron Belcher, Stuart Smolen, Jon Van Loo, Iris Zhang, and the three practice areas, and the routes light up automatically.

Header refinements: the Plan 01 SiteHeader has a flat nav with no "active route" indicator. This plan adds `aria-current="page"` when the current route matches (uses the `currentPath` prop). It also makes the nav usable at viewports < 768px by stacking vertically (per UI-SPEC.md §1 "Responsive: On viewports < 768px, the nav collapses to a single visible link to a future menu (Phase 2 adds the menu UI; Phase 1 ships a stacked text list as the placeholder)").

Footer refinements: confirm Plan 01's locations line includes both addresses; add `<a href="mailto:intake@bsvlaw.com">` link for the intake email.
</rationale>
