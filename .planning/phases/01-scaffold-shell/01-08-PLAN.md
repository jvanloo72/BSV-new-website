  <name>Task 2 (CHECKPOINT): Enable branch protection on main; merge the Phase 1 sign-off PR</name>
  <what-built>The CI workflow proved itself in Task 1 (it ran green on a real PR). Now enable branch protection on `main` so future PRs CANNOT merge without a green CI run.</what-built>
  <how-to-verify>
1. Open https://github.com/jvanloo72/BSV-new-website/settings/branches in your browser.

2. Click **Add classic branch protection rule** (or "Add rule" depending on the GitHub UI version).

3. Configure:
   - **Branch name pattern**: `main`.
   - Check: **Require status checks to pass before merging**.
     - Search and add the required check: **`build-and-test`** (this is the job name from `.github/workflows/ci.yml`).
     - Check: **Require branches to be up to date before merging**.
   - Optional but recommended: **Require a pull request before merging** (prevents direct pushes to `main`).
   - Click **Create** (or "Save changes").

4. **Test the gate.** Go back to the Phase 1 sign-off PR opened in Task 1. The **Merge** button should be enabled (CI was green). Merge it.

5. After merge:
   - Verify the production Vercel deploy auto-runs (Vercel-GitHub integration handles this — main pushes auto-deploy to production).
   - Confirm the production URL works (though Phase 1 hasn't configured a custom domain — that's Phase 7; for now the production URL is on `*.vercel.app` as well).

6. **Sanity-check the gate.** Briefly verify branch protection works by attempting a direct push to main:
   ```powershell
   git checkout main
   "test" | Add-Content README.md
   git commit -am "test direct push"
   git push origin main
   ```
   The push should be REJECTED (if you also checked "Require a pull request before merging" — and if not, the test commit will go through but CI will run on main and you can see the gate works on PRs).

   Clean up: `git reset --hard HEAD~1` (drops the test commit locally).
  </how-to-verify>
