    Then add seven Phase 1 entries, each with the structure `## YYYY-MM-DD — Phase N — Title`, `**What was decided:**`, `**Why:**`, `**Teaching insight:**`.

    The seven entries to seed:

    1. **Astro 6 + Tailwind v4 + Vercel + MDX + sitemap as the stack.**
       Why: locked in `.claude/CLAUDE.md`. Astro fits a content-driven marketing site (fast static output, MDX for blog); Tailwind v4 keeps styling fast and CSS-first; Vercel auto-deploys from GitHub.
       Teaching insight: For a content-heavy marketing site for a non-technical owner, "boring static" beats "exciting dynamic" every time — Markdown + MDX content is editable in the GitHub web editor, no CMS to maintain.

    2. **CSP ships in Report-Only mode through Phases 1–6; enforce in Phase 7 (D-15).**
       Why: Once CSP enforce hits production, any inline-style or third-party load that wasn't accounted for breaks the page. Report-only logs violations without blocking; the soak across Phases 3–6 collects the real-world data that lets Phase 7 enforce with confidence.
       Teaching insight: Security headers are easier to ratchet UP gradually than to roll back from a broken page in production. "Observe before enforce" is the pattern.

    3. **vercel.json owns the security headers; Astro's `security.csp` config is NOT enabled (RESEARCH.md Pitfall A2).**
       Why: Astro's `security.csp` injects CSP via `<meta http-equiv>`, which Safari ignores for Report-Only. HTTP response headers via `vercel.json` are respected by every browser and apply uniformly across static + function responses.
       Teaching insight: "Use the platform" is the rule, but only after you check the platform actually delivers the feature reliably. Two equivalent-looking config options can have very different production behavior.

    4. **gitleaks is installed as a Go binary, NOT the npm package (RESEARCH.md Pitfall A1).**
       Why: The npm `gitleaks@1.0.0` package is a slopsquat — a single-version, no-stars package by an unrelated author. The legitimate gitleaks lives at `github.com/gitleaks/gitleaks/releases`.
       Teaching insight: When a CONTEXT.md says "install gitleaks," the planner's first instinct should be to verify the source, not assume `npm install`. Slopsquatting is the supply-chain attack of the 2020s.

    5. **Five Zod-typed content collections with cross-collection `reference()` typing (FOUND-03, FOUND-04).**
       Why: A non-coding partner edits MDX in the GitHub web editor. Without schemas, a typo in a frontmatter field name fails silently. With Zod schemas, the build catches the typo at compile time, BEFORE anything reaches a preview deploy.
       Teaching insight: Static type-checking at the content layer is the single highest-leverage decision for a content-driven site with a non-technical author.

    6. **Tailwind v4 token names are locked across the Phase 2 palette swap (D-22).**
       Why: Every component reads tokens like `--color-text`, `--color-accent`, etc. Phase 2 changes the VALUES of those tokens to lock the chosen palette; the NAMES stay the same. This lets the entire palette ship as a single CSS file edit later.
       Teaching insight: When you can't decide a design value yet, name the slot now and fill it later. Stable names + late-bound values is a pattern that scales well.

    7. **The disclaimer is a single component reading from a single JSON file (D-03, D-09, D-10).**
       Why: California bar rules require disclaimers on every page. If a future change updates the wording, it MUST update every page — not just one. A single `disclaimers.json` keyed by id + a `<Disclaimer id="..." />` component means one edit propagates everywhere.
       Teaching insight: Compliance text is exactly the kind of content that drifts when scattered. Centralize it once; let the build enforce that every consumer sees the same version.

    End with a `## How to add a new entry` note: each phase appends entries during its build; the orchestrator may automate this via the gsd-transition workflow.
