The crawl test pattern (RESEARCH.md §"Pattern 8"):
1. Fetch the sitemap (try `/sitemap-0.xml` first; if 404, try `/sitemap-index.xml` then `/sitemap.xml` — per RESEARCH.md A3, the exact filename should be confirmed from the actual build output).
2. Parse XML with Cheerio (xmlMode: true).
3. Extract every `<loc>` URL.
4. For each URL: fetch the path, parse HTML, assert footer text contains FOOTER_DISCLAIMER_FRAGMENT.

The webServer config in `playwright.config.ts` (Plan 00 created) ALREADY uses `npm run build && npx astro preview` — that is what RESEARCH.md Pitfall A5 requires (preview, not dev). Verify in Task 3 that this config is correct.

GitHub Actions workflow shape (RESEARCH.md §"Pattern 9"):
- Triggers: pull_request to main, push to main.
- Job: build-and-test on ubuntu-latest.
- Steps: checkout (fetch-depth: 0), setup-node@v5 (Node 22), npm ci, astro check (added per Plan 02's check requirement), npm run build, playwright install --with-deps chromium, npm run test:disclaimer (which now actually runs), npm run lint:legal (Phase 1 placeholder script), gitleaks/gitleaks-action@v2.

Per RESEARCH.md A5, `actions/checkout@v5` and `actions/setup-node@v5` are the assumed 2026 major versions. If a CI run fails because v5 doesn't exist, Plan 08's final verification will catch it and the planner falls back to v4 (this is acceptable — the failure mode is immediate and easy to fix).

<rationale>
The disclaimer crawl is the single most important Phase 1 test. Per `.claude/CLAUDE.md` ("Attorney-client disclaimer on every blog post, practice area page, contact form, footer disclaimer in the footer on every page"), the disclaimer is a non-negotiable law-firm-website compliance gate. The crawl test ENFORCES that gate. If a future change introduces a route that bypasses BaseLayout (or wraps it in a layout that forgets `<SiteFooter />`), the test fails and the PR is blocked from merging — the "Future Jon" defence per RESEARCH.md §"Anti-Patterns to Avoid."

Critical implementation note: the sitemap filename produced by `@astrojs/sitemap` is `sitemap-index.xml` + one or more `sitemap-N.xml` files, OR (for small sites) just `sitemap-0.xml`. RESEARCH.md A3 flags this — the test must probe for either filename. The Task 1 implementation tries `sitemap-0.xml` first, falls back to `sitemap-index.xml` (and then follows the index to the child sitemap), and finally `sitemap.xml`. Plan 04's summary should record which filename actually appeared in `dist/` after build.

The `lint:legal` script in `package.json` is a Phase 1 placeholder (`echo`-only per Plan 01). Plan 4 will replace it with a real Rule 7.4 banned-terms scan. The CI workflow runs it as a no-op in Phase 1 just to confirm the script wires up correctly.

For BaseLayout integration coverage: Task 2 implements `tests/baselayout.spec.ts` to assert the homepage has the firm name in `<header>` AND the disclaimer fragment in `<footer>`. This is complementary to the crawl test (which iterates every route) — the BaseLayout test is the focused "the layout reached the homepage" sanity check.
</rationale>
