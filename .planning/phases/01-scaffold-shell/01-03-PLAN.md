<rationale>
This plan establishes the JSON-LD + SEO contract once. Phase 4 adds `Person` JSON-LD via AttorneyLayout's slot transfer; Phase 4 adds `FAQPage` JSON-LD via PracticeAreaLayout; Phase 5 adds `Article` JSON-LD via BlogPostLayout. None of those phases needs to modify BaseLayout — they only inject into its named `head` slot.

`schema-dts` types (`WithContext<LegalService>`, `PostalAddress`, etc.) make a typo a TypeScript compile error rather than a silent SEO bug. RESEARCH.md §"Don't Hand-Roll" explicitly calls this out.

The `set:html` directive on the `<script>` tag is the canonical Astro pattern. Per RESEARCH.md §"Pattern 5," the input to JsonLd in Phase 1 is always compile-time constant data from `src/lib/jsonld.ts`, so the XSS surface is limited to build-time accidents. No runtime user input touches this pipeline in Phase 1; that changes in Phase 6's contact form, which uses a different code path entirely.

SkipToContent is a single anchor that targets `#main` (the id on BaseLayout's `<main>`). When focused (via Tab key), it becomes visible; when unfocused, it's `sr-only`. This is the WCAG 2.1 baseline (A11Y-03 will be fully verified in Phase 7).

Implementation note on `dist/index.html` JSON-LD verification: Astro inlines the `<script type="application/ld+json">` into the rendered HTML. The jsonld-legalservice test reads `dist/index.html`, extracts the JSON-LD script content, and parses it. Run AFTER `npm run build`.
</rationale>
