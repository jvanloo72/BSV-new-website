D-04 attorneys schema (RESEARCH.md §"Pattern 2"):
```
schema: ({ image }) => z.object({
  name: z.string(), slug: z.string(),
  title: z.enum(['Partner', 'Associate', 'Counsel']),
  barAdmissions: z.array(z.string()).min(1),
  education: z.array(z.object({ degree, school, year?, honors? })),
  focus: z.string(),
  priorFirms: z.array(z.string()).default([]),
  representativeDeals: z.array(z.object({ parties, value?, role?, cleared: boolean })).default([]),
  recognition: z.array(z.string()).default([]),
  clerkship: z.string().optional(),
  languages: z.array(z.string()).default(['English']),
  email: z.string().email(),
  phone: z.string().optional(),
  headshot: image(),
  headshotAlt: z.string(),
  order: z.number(),
  draft: z.boolean().default(false),
})
```

D-07 testimonials schema: optional `practiceArea: reference('practiceAreas').optional()`.

D-08 disclaimers schema: already established in Plan 01 — DO NOT modify it.

<rationale>
The collection schemas are the safety net for a non-coding editor. Jon will add a new attorney bio by copying `placeholder-attorney.mdx`, editing the frontmatter, and committing via the GitHub web editor. If he forgets a required field, the build fails with a typed Zod error — caught by CI before anything reaches the public preview URL.

The placeholder MDX files are NOT real content. They are minimum-valid-shape entries proving the schema works end-to-end and giving Plan 03's specialized layouts something to render against. All four MDX placeholders are marked `draft: true` (except testimonials, where the schema has no `draft` field — there it's just a placeholder file).

The negative test (D-24) copies `tests/fixtures/broken-blog-post.mdx` into `src/content/blog/` at test time, runs `npm run build`, asserts it exits non-zero with a Zod error message in stderr, then removes the file. This proves FOUND-04 end-to-end. Critical: the test MUST clean up its temporary file in a `finally` block — leaving the broken file behind would break every subsequent build.

The placeholder headshot is a 1×1 SVG (or similar trivial image) that satisfies Astro's `image()` validation. Real headshots are TBD (per `.claude/CLAUDE.md` "All headshots TBD — build with tasteful placeholders").
</rationale>
