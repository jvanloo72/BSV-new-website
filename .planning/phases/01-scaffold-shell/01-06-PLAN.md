`src/pages/api/csp-report.ts` contract (RESEARCH.md §"Pattern 7"):
```typescript
export const prerender = false;  // ensure serverless function, not static
export const POST: APIRoute = async ({ request }) => { ... };
```
Returns: 204 on success, 400 on bad input, 413 on body > 8 KB.

The vercel.json from Plan 01 already references `/api/csp-report` in the CSP `report-uri` directive. With `@astrojs/vercel@10.0.7` adapter (locked in Plan 01), any `.ts` file under `src/pages/api/` automatically becomes a Vercel serverless function. No additional `astro.config.mjs` changes required.

The gitleaks binary install is OS-specific. RESEARCH.md §"Environment Availability" notes: download from `https://github.com/gitleaks/gitleaks/releases/latest/download/gitleaks_<version>_windows_x64.zip`, extract `gitleaks.exe` to a PATH directory (recommended: `C:\Users\jonva\bin\`).

GitHub push protection is a free feature for personal repos in 2026 (per RESEARCH.md A4). Enabled via web UI: Settings → Code security → Secret scanning → Push protection → enable.
</interfaces>

<rationale>
The CSP report endpoint MUST set `prerender = false` because Astro defaults `output: 'static'` (Plan 01); without this, the endpoint would be pre-rendered to a static file and the POST would 404. The `@astrojs/vercel` adapter wires the `prerender: false` route into a serverless function automatically.

The endpoint uses streaming reads (`request.body.getReader()`) rather than `await request.text()` because the latter loads the entire payload into memory before applying the size limit. With streaming reads, we can short-circuit at 8 KB without buffering anything larger. CSP reports are typically ~500 bytes; 8 KB is a generous cap.

`console.warn` logs land in Vercel's function logs (visible in the dashboard → Project → Logs). No DB or third-party log sink in Phase 1 — Phase 6/7 may add structured logging. The endpoint does NOT echo the body back to the browser because CSP reports can contain sensitive page content (URLs, source-code paths).

The local pre-commit hook + GitHub push protection are deliberately redundant. The hook gives instant feedback (commits fail before they're made, no need to re-fetch). Push protection catches the cases where the hook was missing (fresh clone, `git commit --no-verify`, different developer). Both layers are required by SEC-04 and D-17.
</rationale>
