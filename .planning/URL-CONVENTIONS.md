# URL Conventions — BSV Law Website

## Why this file exists

URLs are public commitments. Once the site launches, every slug becomes an
inbound-link target — for referring lawyers, for client emails, for search
engines, and for the next attorney who finds a BSV partner via a Google search
weeks after that first introduction. Renaming a slug after launch breaks every
inbound link, drops search-engine equity that took months to build, and creates
404s in private referral threads we never see. This file documents the slug
format for every kind of page that ships, so the format does not drift between
phases or between authors. **Slugs are locked at first publish and renamed only
through a 301 redirect.**

## Canonical Route List

Flat list of every URL the site ships at v1:

- `/` — homepage
- `/about` — firm history, both office locations, positioning
- `/contact` — contact form (with attorney-client disclaimer)
- `/practice-areas` — practice-areas index
- `/practice-areas/mergers-acquisitions`
- `/practice-areas/intellectual-property-technology-transactions`
- `/practice-areas/tax`
- `/attorneys` — attorneys index
- `/attorneys/aaron-belcher`
- `/attorneys/stuart-smolen`
- `/attorneys/jon-van-loo`
- `/attorneys/iris-zhang`
- `/attorneys/susan-jiang` (ships as `draft: true` until Jon supplies the final bio)
- `/blog` — Insights index (filterable by attorney + practice area)
- `/blog/[slug]` — individual blog post (one URL per post; slug locked at first publish — see "Blog (D-13)" below)
- `/404` — branded not-found page
- `/500` — branded server-error page
- `/sitemap.xml` (or `/sitemap-0.xml` + `/sitemap-index.xml`) — auto-generated by `@astrojs/sitemap`
- `/robots.txt` — auto-generated; references the sitemap
- `/api/csp-report` — Phase 1 only POST endpoint that logs CSP violations during the report-only soak; non-indexable by design and excluded from the sitemap

Any route not on this list is, by default, NOT part of v1. New routes require an
update to this file and (per `## Change Process` below) an entry in
`.planning/DECISIONS.md`.

## Slug Format Rules

### Attorneys (D-11)

Attorney slugs use the `first-last` convention, lowercase, ASCII only, with
spaces replaced by hyphens. No middle initials, no titles, no commas. This
matches the existing bsvlaw.com URL pattern for the four attorneys with known
URLs, so legacy inbound links can be redirected cleanly.

The five locked attorney slugs:

- `aaron-belcher`
- `stuart-smolen`
- `jon-van-loo`
- `iris-zhang`
- `susan-jiang`

**Explicitly excluded:** Nir Fishbien is NOT in this list and is NOT a route on
the site. Per `.claude/CLAUDE.md` and `.planning/FIRM_BRIEF.md`, Nir Fishbien is
not featured on the new site (not in the `attorneys` content collection, not
linked, not indexed). The exclusion is intentional and load-bearing.

If a new attorney joins the firm post-launch, the slug follows the same
`first-last` lowercase pattern and is added to the canonical route list above.

### Practice Areas (D-12)

Practice-area slugs are verbose and hyphenated — the full descriptive phrase,
lowercase, ASCII only, with spaces replaced by hyphens. Verbosity is deliberate:
the slug doubles as on-page SEO and as an unambiguous URL when a referring
lawyer pastes the link into an email.

The three locked practice-area slugs:

- `mergers-acquisitions`
- `intellectual-property-technology-transactions`
- `tax`

Short or abbreviated forms (`ip`, `m-and-a`, `ma`, `iptech`) are NOT used. If a
fourth practice area is ever added, it follows the same verbose-hyphenated
pattern.

### Blog (D-13)

Blog slugs are `kebab-case` derived from the post title — lowercase, ASCII only,
spaces replaced by hyphens, punctuation stripped. Slugs are generated by the
author at draft time and reviewed during the editorial pass before publish.

**THE LOCK CLAUSE (load-bearing):** Once a blog post publishes (`draft: false`,
merged to `main`, deployed to production), its slug is permanent. Any rename
requires a 301 redirect added to `vercel.json` so the old URL does not die.
This rule is enforced **socially**, not in code — any author can technically
change a slug in their MDX frontmatter, but doing so without adding a redirect
is a process violation. The editorial review gate (`reviewed_by` field) is the
checkpoint for catching attempted slug changes before merge.

If a slug must change after publish (typo, factual error, sensitive name in the
URL), the process is:

1. Update the slug in the MDX frontmatter.
2. Add a `redirects` entry in `vercel.json` mapping the old slug to the new one.
3. Log the change in `.planning/DECISIONS.md` with the reason and the redirect.

### Other Pages

`/about` and `/contact` are static single-word slugs. Any future static page
(e.g., `/insights` if "Insights" is ever broken out, or `/co-counsel` if a v2
referrer hub ships) follows the same convention: a single word or short
hyphenated phrase, lowercase, no trailing characters.

Index pages (`/practice-areas`, `/attorneys`, `/blog`) use the plural form of
the collection name and never carry a trailing slash.

## Trailing Slashes

`trailingSlash: 'never'` is set in `astro.config.mjs` (Plan 01 — Walking
Skeleton). Every URL on the site is canonical without a trailing `/`. A user
who types `/about/` is 301-redirected to `/about`. The choice of `'never'` is
deliberate: it avoids the two-canonical-URL problem (where `/about` and
`/about/` both resolve and split search-engine equity) and matches Vercel's
default behavior.

## Change Process

Changing this file — adding a route, renaming a slug, changing a format rule —
requires:

1. **An entry in `.planning/DECISIONS.md`** explaining what changed and why,
   per the Decision Log requirement in `.claude/CLAUDE.md`.
2. **If the change renames an already-published slug**, a 301 redirect entry in
   `vercel.json` so the old URL does not 404. Slug renames without a redirect
   are a process violation.
3. **If the change adds a new route**, an update to the Canonical Route List
   above in the same PR that adds the route's source files.

The file's frontmatter `locked_at` date does NOT change when a single entry is
added or amended — it reflects the original lock date for Phase 1. The Decision
Log is the historical record of every subsequent change.
